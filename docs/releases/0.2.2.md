# 0.2.2 — Read-only guest access

Date: 2026-10-04. Web release. Native packages remain at their published version.

- Guests can browse public posts and public profiles through the existing `/home`, `/posts/[id]` and `/profile/[username]` URLs.
- The proxy routes anonymous reads to dedicated guest components. The member layout, notifications, comments and action controls are not mounted there. The shared settings orb offers guests only theme and language choices stored in their browser, with no profile API writes.
- Private profiles, archived posts and posts without a public author are excluded in database queries. Legacy records without explicit public visibility flags fail closed. Guest data selects omit email addresses, location coordinates, account settings and post revision history.
- Guest Profile navigation and direct member-only URLs lead to `/join`, with localized registration and sign-in choices. Google remains the only independent login provider in this release.
- Anonymous web mutations, server actions and member APIs return 401. Auth.js endpoints keep their own OAuth/CSRF validation; mobile requests require a valid signed bearer token or web session. Cron requests retain their secret check.
- Database errors show a localized retry link without granting wider access. Guest responses are not publicly cached.

Verification: `node --test scripts/test-guest-access.cjs`, TypeScript, targeted ESLint, local HTTP checks and production build. Browser visual checks and authenticated provider completion must be reported separately; tests do not create accounts or modify Atlas data.

Results: 26 regression tests passed (six guest-access tests, two guest-settings tests including blocked browser storage, plus 18 existing location tests), TypeScript and targeted ESLint passed, and the production build succeeded. Anonymous HTTP checks confirmed public feed/post access, join redirects and 401 write/API protection against the running local server. Browser automation timed out before a visual inspection could be completed; real Google sign-in was not performed.

Native APK/EXE artifacts remain at their published version. Additional login methods are planned for 0.2.3.
