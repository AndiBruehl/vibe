# 0.2.1 — Location improvements

Date: 2026-09-29. Web release; native installers remain at 0.2.0.

Place searches return up to five candidates without changing the saved location. Selecting a candidate, tapping the settings map or completing coordinates saves after a short pause. Approximate sharing rounds all sources to one decimal and removes the street label; precise sharing uses five decimals. The member map also rounds existing approximate records when reading them.

Owners can remove a post's location from its map, with confirmation and a server-side ownership check. Profile sharing can be stopped to clear its stored location. Maps show the last update in UTC and explicitly state that the location is not live.

English and German feedback distinguishes missing places, provider outages and save failures. Drafts are scoped to the profile in session storage, restored without automatic publication, and retained on failure. Coordinate/map entry remains available when search fails.

Request timeouts cover response-body reading as well as connection setup. Invalid saved coordinates or malformed search candidates show recoverable feedback and preserve inputs instead of clearing them or crashing the picker.

Validation: `node --test scripts/test-location-route.cjs scripts/test-location-editor.cjs scripts/test-post-location-removal.cjs`; All 18 tests passed, as did TypeScript, targeted ESLint and the production build. These are mocked regression checks, not a live Atlas or geocoding-provider integration test.

Published APK/EXE artifacts and release manifest remain on 0.2.0 for this web-only release.
