# 0.2.3 — Additional sign-in methods

Date: 2026-10-04. Local implementation; not published.

Google remains available. Microsoft Entra ID, Apple and Discord are added as optional Auth.js providers, but each provider is only registered when its complete server-side configuration exists. Missing credentials therefore hide the method and do not break the existing Google flow.

Email/password registration requires a configured Resend API key, sender address and HTTPS auth origin. Registration, setup and reset requests return an intentionally neutral response, are rate-limited, and send a one-time link. Passwords must be 12–128 characters and are stored only as scrypt-derived hashes. Reset proofs are single-use, expire after 20 minutes, and increment a credential version so older sessions can be invalidated.

OAuth identities are stored separately. A new provider never merges into an existing account based on matching email alone. A signed-in member starts explicit linking from Settings; conflicts, expired proofs and unavailable providers return localized feedback. Provider email claims must be verified; Microsoft users can confirm their email through a one-time proof when the provider does not supply a verified claim.

The account endpoint checks the request origin, caps request size, rate-limits proof operations and never logs token material. Confirmation tokens are placed in a URL fragment and removed from browser history before use. Email delivery has a timeout and deletes the pending proof when delivery fails.

Verification: auth security tests, TypeScript, targeted ESLint and production build. No provider credentials were added to the repository, and no real account, password, email or OAuth consent was created during local testing. APK/EXE releases remain at their previous versions.
