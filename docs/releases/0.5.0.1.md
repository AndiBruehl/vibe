# VIBE 0.5.0.1 🛡️ — Mobile auth bridge recovery fix

Release date: 2026-10-12. Local development step; not deployed.

## Problem

A freshly installed Android APK can open the WebView with a stored mobile token and submit it to `/api/mobile/auth/web`. If the backend rejects that bridge request with an HTTP error, Android shows `Webseite nicht verfügbar` / `net::ERR_HTTP_RESPONSE_CODE_FAILURE` instead of returning to a recoverable login state.

## Changes

- Validate the submitted mobile token before calling Auth.js `signIn("mobile")`.
- Redirect missing, invalid or expired bridge tokens to the login/join recovery path instead of returning an HTTP failure page.
- Catch non-redirect Auth.js bridge failures and recover through the same redirect.
- Android now clears the stored mobile token when `/api/mobile/auth/web` returns an HTTP error, then shows the native login screen with a clear expired-session message.

- Android package metadata is prepared for 0.5.0.1 with versionCode 101.
- Desktop package metadata is prepared for 0.5.0.1.

## Still true

Published APK/EXE metadata remains pinned to accepted 0.4.1 artifacts until rebuilt, signed and manually accepted.
