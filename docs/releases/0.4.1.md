# VIBE 0.4.1 — Native sign-in recovery

Release date: 2026-10-08. Web, Android and desktop versions are 0.4.1; release metadata points to the matching beta artifacts included in this release.

- Active Android WebView shell now offers Google and Discord with account-linking guidance and acknowledgement.
- A shared mobile OAuth entry preserves the existing Google endpoint for older APKs. Google/Discord use the existing Auth.js provider configuration and account-linking safeguards.
- Mobile callbacks accept only the exact VIBE callback with a valid attempt state. Expired/malformed attempts and duplicate completion are rejected or ignored; the new token is validated before replacing the stored session.
- Android linking opens the system browser with a short-lived, one-use linking proof issued by the authenticated account endpoint. Completion refreshes Settings without replacing the app session; cancellation leaves Settings in place.
- Errors and cancellations return to the app with a retry message. A cold-start callback can resume a pending login.
- Deleted profiles are never recreated by the mobile completion endpoint.
- Desktop offline recovery returns to the last same-origin, non-API VIBE page; it does not replay OAuth codes or clear cookies.
- Settings shows Web BETA 0.4.1 with the rocket emoji (🚀); Home changelog and download metadata also show 0.4.1. Installed native versions remain read from the actual app user agent.
- A database failure while checking a linking attempt now produces a retry message instead of falsely claiming that the attempt expired.

Manual acceptance still required: real Google/Discord consent on Android and Windows, linking with different emails, cancellation, process termination, and intermittent connectivity. Automated tests do not prove provider consent or device integration.

The new APK requires the 0.4.1 backend to be reachable. Default builds use production; local-only web changes are not automatically available to a phone.
