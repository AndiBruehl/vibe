# 0.3.0 Plan - Restricted guest access

Date prepared: 2026-10-05.

## Goal

Make logged-out VIBE access intentionally read-only. Guests can view public profiles and public posts, choose local theme/language, and create or sign in to an account from Profile. Everything else stays member-only.

## Scope

- Public post and profile viewing for guests.
- Server-side blocking for guest write actions and private/member routes.
- Guest navigation without member-only controls.
- Small guest settings orb with theme and language only.
- Profile click path to account creation or sign-in.
- Regression tests for route access, API write protection, public rendering and member redirects.

## Out of scope for the first 0.3 step

- Microsoft login.
- Apple login.
- Email/password login.
- Native APK/EXE rebuilds unless web behavior requires wrapper changes.
- Automatic provider merging beyond the existing explicit Google/Discord linking rules.

## Acceptance

- Anonymous users can open public `/home`, `/posts/[id]` and `/profile/[username]` content.
- Anonymous users cannot comment, post, like, follow, message, bookmark, save, edit settings or call member APIs.
- Private profiles, archived posts and missing visibility flags fail closed.
- Authenticated members keep their current behavior.
- Tests cover the guest/member boundary and the UI entry point to account creation.
