# 0.3.0 - Restricted guest access

Date: 2026-10-06. Web release; native APK/EXE artifacts remain at their actual published version.

- Logged-out visitors can view public posts, public profile pages and the public Profiles directory.
- Anonymous `/home`, `/posts/[id]`, `/profile/[username]` and `/profiles` requests are rewritten to dedicated guest pages.
- Guests cannot post, comment, like, follow, message, bookmark, save, edit settings or call member-only APIs.
- The guest Profile navigation opens account creation or sign-in. Public Profiles is a separate read-only destination.
- The guest quick settings orb only exposes local theme and language choices.
- Public profile directory queries filter private profiles and return public fields only.
- Public profile pages preserve safe personalization fields: header layout, background, text color, profile accent, avatar frame and profile badges.
- Admin and Verified status labels are spelled out on profile headers only; compact contexts such as comments, feeds and directories show icons only.

Validation: guest-access and guest-settings regression tests passed, including anonymous route rewrites, API write protection, public profile/post data selection and storage-blocked guest preferences. TypeScript and targeted ESLint passed.

Local development note: on this Windows desktop, the VIBE dev server must be started with elevated rights so the Node/Prisma process can reach MongoDB Atlas on port 27017. With that process context, public posts and profiles load from the live database.
