# 0.2.4 — Account linking and recovery

Date: 2026-10-05. Web release; deployment completion must be verified separately after push.

- Linked Google and Discord methods share a compact overview with green confirmation checks and connection dates; duplicate linked buttons are hidden.
- Cancelling provider linking returns to Sign-in methods. The last available method has no Remove button, and removal feedback has its own spacing.
- Explicit unlink confirmation and server-side protection preserve one available login method. A shared transactional write protects against concurrent removals.
- Linked methods cannot be changed when their state failed to load.
- Dedicated bilingual conflict page with recovery and support links.
- Clearer OAuth error messages without exposing account details.
- Admin deletion receipts commit with deletion and contain no deleted-user login data.
- Web version is 0.2.4; native wrappers display their actual installed version.

Validation: 33 automated auth tests, TypeScript and targeted ESLint passed. Public provider callback URLs and anonymous session responses passed on localhost and https://vibe-social-network.vercel.app. The production checks are read-only and apply to the currently deployed version.

Outstanding acceptance checks: complete Google and Discord OAuth consent, new registration, linking both providers, unlinking either while retaining access, concurrent real database removals, and deleting a disposable account. Database write/rollback and browser layout were not verified against live user data. APK/EXE artifacts remain 0.2.0 and were not rebuilt or renamed.
